# The CUET scraper

Captures **cuet.ac.bd** for the Cortex pipeline. API-first: roughly 530 of the
documents come from CUET's own JSON API in about 45 requests, and the headless
browser is used only for the handful of pages the API cannot reach.

Specification: [`docs/cuet/SPEC.md`](../../../../../docs/cuet/SPEC.md) (Part 1)
and [`docs/cuet/SPEC_PART2.md`](../../../../../docs/cuet/SPEC_PART2.md). Every
`Spec §6.3` in the code points into those.

Output: [`engine/corpus/cuet/`](../../../../corpus/cuet/), which has its own
README describing the corpus for whoever embeds it.

---

## 1. Four people, four portions

The site is split into **portions**. A portion is one person's slice: the
builders that produce its documents, the folders those documents land in, and
the part of the live site they correspond to.

```bash
python -m engine.crawler.cuet --list-portions
```

| Portion | Owner | On the website | Writes into | Docs |
|---|---|---|---|---|
| `general` | UNASSIGNED | About menu, campus life, prospective students, research pages, Student Organizations | `_cms/`, `home/organizations/` | 23 |
| `academic` | UNASSIGNED | Academic menu: departments, faculties, institutes, centres, curricula | `academic/departments/`, `academic/faculty/`, `academic/institutes/`, `academic/centers/`, `academic/information/` | 32 |
| `news-events` | UNASSIGNED | News & Events menu | `news-events/news/`, `news-events/event-details/` | 160 |
| `notices` | UNASSIGNED | Notices menu and the top-bar notice links | `top-bar/notices/`, `admission/notices/`, `academic/notices/`, `_unsorted/notices/` | 22 |
| `browser` | (stage 4) | The listing pages themselves | `news-events/listing/` | 3 |

**Put your name in `builders/__init__.py` on day one.** `UNASSIGNED` means
nobody is checking that portion, which is how a whole content type goes missing
without anybody noticing.

`browser` is not a person's portion. It is whatever stage 4 renders, decided by
the residual URL plan rather than by whose slice it is.

### Why the split works

Each portion writes its own folders and its own shard. Nothing is shared, so
two people running at the same time never write the same path:

```bash
python -m engine.crawler.cuet --stage content --portion academic
```

writes `academic/**` and `_shards/academic.json`, and touches nothing else.

The corpus-wide files are assembled afterwards, by anybody:

```bash
python -m engine.crawler.cuet --stage merge
```

`documents.jsonl`, `pages.jsonl` and `manifest.json` are **generated and
gitignored**. Committing them would mean four people conflicting on the same
file in every pull request, in a format nobody can hand-merge. The shards are
committed instead: one file per portion, one owner each. Merging is
deterministic, so regenerating is a real answer to any disagreement.

## 2. Where each folder comes from

Two mappings matter, and they are different questions.

**Folder to website** — which page a document came from — is in the corpus
README, regenerated by `handover.py`, because that is the file somebody has
open when a document looks wrong. Read it there:
[`corpus/cuet/README.md`](../../../../corpus/cuet/README.md).

**Folder to code** — which module wrote it — is this:

| Folder | Written by | From which endpoint |
|---|---|---|
| `_cms/` | `builders/general.py` → `build_cms` | `/general-settings` |
| `home/organizations/` | `builders/general.py` → `build_student_organizations` | `/student-organizations` |
| `academic/departments/`, `faculty/`, `institutes/`, `centers/` | `builders/academic.py` → `build_entities` | `/administrative-departments` + per-entity detail |
| `academic/information/` | `builders/academic.py` → `build_curricula` | `/academic-curriculums` |
| `news-events/news/` | `builders/news.py` → `build_news` | `/news` |
| `news-events/event-details/` | `builders/news.py` → `build_events` | `/events` |
| `top-bar/`, `admission/`, `academic/notices/`, `_unsorted/notices/` | `builders/notices.py` → `build_notices` | `/notices` |
| `news-events/listing/` | `capture.py` | the browser, no endpoint |

Sections themselves are data, not code: `config.SECTIONS` maps a URL to a
folder and `config.GROUPS` gives the second level. Adding a part of the site
means adding a rule there, not writing a branch.

Note that `notices` writes into `academic/notices/`, a folder the `academic`
portion also writes into. That is deliberate — the academic-calendar notices
belong under Academic on the website — and it is safe, because documents are
named from their own id and never collide. Only the merged files are shared,
and those are generated.

## 3. The modules

```
cuet/
├── __main__.py     CLI: stage dispatch, run bookkeeping
├── config.py       every tunable value, with the evidence for each
├── paths.py        canonicalisation, stable ids, filesystem naming
├── api.py          polite HTTP: rate limit, retries, robots
│
├── discover.py     stage 1 — fetch every endpoint, save the raw bytes
├── builders/       stage 2 — payloads to documents, ONE MODULE PER PORTION
│   ├── __init__.py   the portion registry. The one shared file, kept tiny.
│   ├── base.py       the document model and the shared helpers
│   ├── general.py    CMS pages, student organisations
│   ├── academic.py   departments, faculties, institutes, centres, curricula
│   ├── news.py       news, events
│   └── notices.py    every notice type
├── content.py      stage 2 — writes documents and the per-portion shard
├── capture.py      stage 4 — the browser, for what the API cannot reach
├── files.py        stage 5 — download the linked PDFs
├── merge.py        assembles the shards into the corpus
├── audit.py        re-derives the endpoint list from the live JS bundles
├── markdown.py     HTML to markdown
└── handover.py     the corpus README, pages.jsonl and manifest.json
```

**Add a builder to your own module.** `builders/__init__.py` is the only file
all four of you touch, and adding a portion there is one import and one entry.
That is a three-line conflict at worst, instead of a three-way merge of a
700-line module — which is what this used to be.

## 4. Running it

```bash
cd engine
uv sync --extra dev                     # add --extra browser for stage 4

python -m engine.crawler.cuet --list-portions
python -m engine.crawler.cuet --stage discover              # ~45 requests
python -m engine.crawler.cuet --stage content --portion academic
python -m engine.crawler.cuet --stage merge
```

| Stage | Does | Network |
|---|---|---|
| `discover` | Fetch all 17 endpoints, save `_meta/api_dump.json` | yes |
| `content` | Payloads to documents and a shard. `--portion` selects | no |
| `merge` | Shards to `documents.jsonl`, `pages.jsonl`, `manifest.json` | no |
| `capture` | Render the residual pages. `--section` selects | yes, browser |
| `files` | Download the linked PDFs | yes |
| `audit` | Re-derive the endpoint list from the live JS bundles | yes |
| `all` | discover, content, files, audit, merge | yes |

`--out` overrides the destination; it defaults to `engine/corpus/cuet`
regardless of the directory you started from. Point it somewhere disposable
for a trial run.

Everything except `discover`, `capture`, `files` and `audit` runs offline
against the saved dump, so iterating on a builder costs no requests.

## 5. Before you touch anything

**Politeness is not negotiable.** `DELAY = 1.5` seconds per host, three
concurrent requests at most, and a real contact address in the User-Agent.
There is no `robots.txt` on cuet.ac.bd — it returns 404 — which does not mean
permission. It means the site never got to state a limit, so the delay and the
User-Agent are the only restraint left. If CUET starts refusing, stop and raise
it rather than working around it.

**Nothing behind a login, ever.** A student account must never be used to reach
content a member of the public could not. Part 2 §9.1.

**No images.** Not a default, a requirement: nothing downstream can embed a
PNG. They are filtered by URL at one chokepoint in `paths.is_image_url`,
because there are already five image-bearing JSON field names across two
endpoints and the next endpoint will invent another.

**Read the comment before changing a constant.** The numbers in `config.py`
that look arbitrary were measured. `EMPTY_RENDER_THRESHOLD` and
`CAPTURE_CONCURRENCY` in particular each record a bug that silently saved
empty pages as if they were content.

## 6. Tests

```bash
uv run pytest tests/crawler/cuet -q
```

`test_portions.py` is the one to keep green if you change the split. Every test
in it describes a way four people collide: two portions claiming one builder,
a shard overwriting another, a merge that drops a portion silently, `linked_from`
losing every source but the last.
